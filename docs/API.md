# API

Contract for the HTTP API, the event format, and the internal gRPC service. The HTTP API is JSON over HTTP/1.1 or
HTTP/2, versioned in the path. A machine-readable OpenAPI 3.1 document is generated by springdoc and a snapshot is
committed as `api/openapi.yaml`; a build test fails when the generated document differs from the snapshot.

> **Status:** target contract. The code currently implements only `POST /api/v1/events`, and its storage path changes
> in milestone M1 (see the roadmap in the [README](../README.md#roadmap)).

## 1. Standards followed

| Concern | Standard |
|---|---|
| HTTP semantics, methods, status codes, caching | RFC 9110, RFC 9111 |
| Error bodies | RFC 9457 Problem Details (`application/problem+json`) |
| Authentication | `Authorization: Bearer` (RFC 6750), `WWW-Authenticate` on `401` |
| Timestamps | RFC 3339 in UTC, `Z` suffix |
| Identifiers | UUID version 7 (RFC 9562) for server-generated ids |
| Links and pagination | `Link` header (RFC 8288) plus a cursor in the body |
| Events | CloudEvents 1.0 with the HTTP protocol binding (structured, binary, batch) |
| Streaming | Server-Sent Events as defined by the WHATWG HTML Living Standard |
| Trace propagation | W3C Trace Context (`traceparent`, `tracestate`) |
| Metrics exposition | Prometheus text format, Prometheus naming guidelines |
| Health probes | Kubernetes liveness and readiness semantics |
| Internal RPC | gRPC, protobuf, Google API design guide naming, `grpc.health.v1` |
| Deprecation | `Deprecation` (RFC 9745) and `Sunset` (RFC 8594) headers |

## 2. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1`. Only additive changes inside `v1`. A breaking change is a new version. |
| Resources | Plural nouns, no verbs. Read endpoints use `GET` only. `PUT`, `PATCH`, `DELETE` are not part of `v1`. |
| JSON fields and query parameters | `camelCase` |
| Enum values | lowercase `snake_case`, the same string in the API, the database, and the agent |
| Units | In the field name, base units last: `freshnessSeconds`, `costUsd` |
| Ratios | Number from 0 to 1, field name ends in `Ratio` |
| Unknown request fields or parameters | `400`. Never silently ignored. |
| Content type | `application/json` unless stated |
| Request correlation | Accept and return `traceparent`. Every log line carries the trace id. |

### Errors

Every error is `application/problem+json` from one global handler. No stack traces. No internal messages.

```json
{
  "type": "urn:bromo:problem:invalid-event",
  "title": "Invalid event",
  "status": 400,
  "detail": "The event is not valid CloudEvents 1.0.",
  "instance": "/api/v1/events",
  "errors": [{ "pointer": "/id", "detail": "must not be empty" }]
}
```

`type` is a URN, one per row below. `errors[].pointer` is a JSON Pointer (RFC 6901) into the request body.

| Status | `type` suffix | When |
|---|---|---|
| 400 | `invalid-request`, `invalid-event` | Malformed JSON, unknown field, invalid CloudEvent |
| 401 | `unauthenticated` | Missing or wrong credential. Response includes `WWW-Authenticate: Bearer realm="bromo"`. |
| 403 | `forbidden` | Valid credential of the wrong kind (a chat token on ingest) |
| 404 | `not-found` | Unknown metric or finding |
| 413 | `content-too-large` | Event or batch above the configured limit |
| 415 | `unsupported-media-type` | Content type not accepted by the endpoint |
| 422 | `unprocessable` | Syntactically valid but rejected, for example a time range too wide |
| 429 | `rate-limited`, `daily-budget-exhausted` | Rate limit or LLM spend cap. Includes `Retry-After` (seconds). |
| 503 | `unavailable` | ClickHouse unavailable. Includes `Retry-After` when known. |

Errors never reveal whether a credential exists.

### Authentication

| Endpoint group | Credential |
|---|---|
| Ingest | `Authorization: Bearer <ingest key>` |
| Chat | `Authorization: Bearer <chat token>` |
| Pipeline status, metrics, findings | None when `BROMO_PUBLIC_READ=true`, otherwise a chat token |
| Management | Internal network only, separate port |

Keys and tokens are compared in constant time. The `X-` header prefix is not used (RFC 6648).

### Caching and CORS

Authenticated responses are `Cache-Control: no-store`. Public read responses are `Cache-Control: public, max-age=5`.
`GET /findings/{id}` is immutable and carries an `ETag`. The UI is served from the same origin, so CORS is disabled by
default.

### Pagination

Cursor pagination. `limit` (default 20, maximum 100) and an opaque `cursor`. Responses are
`{ "items": [...], "nextCursor": "..." | null }` and add `Link: <...>; rel="next"` when more items exist. Offset
pagination is not offered, it is unstable on append-only data.

### Retries and idempotency

| Endpoint | Safe to retry | Why |
|---|---|---|
| `POST /events` | Yes | The event's own `source` and `id` are the idempotency key. The warehouse collapses duplicates. No `Idempotency-Key` header is needed because the intent key is already in the payload. |
| `GET` endpoints | Yes | Read only |
| `POST /chat` | No | Each call can spend money. Clients must not retry automatically. |

Duplicate collapse happens on merge, so aggregates can briefly over-count. See [DATA.md](DATA.md#delivery-guarantees).

| Method and path | Purpose | Auth |
|---|---|---|
| `POST /api/v1/events` | Ingest one or many events | ingest key |
| `GET /api/v1/pipeline/status` | Freshness, lag, rejects, reconciliation | public read or token |
| `GET /api/v1/metrics` | Metric registry | public read or token |
| `GET /api/v1/metrics/{name}/series` | Time series for one metric | public read or token |
| `GET /api/v1/findings` | List findings | public read or token |

| `POST /api/v1/chat` | Ask the agent, streamed | chat token |

## 4. Ingest

`POST /api/v1/events` follows the CloudEvents HTTP protocol binding.

| Mode | `Content-Type` | Body |
|---|---|---|
| Structured | `application/cloudevents+json` | One event as JSON |
| Binary | The event's `datacontenttype` (`application/json`) | `data` only, attributes in `ce-*` headers |
| Batch | `application/cloudevents-batch+json` | JSON array, up to `BROMO_MAX_BATCH_EVENTS` events |

Validation, at the boundary only:

| Attribute | Rule |
|---|---|
| `specversion` | `1.0` |
| `id` | Non-empty, at most 256 characters |
| `source` | Non-empty, at most 1024 characters (a URI-reference is recommended) |
| `type` | Matches `^[a-z0-9][a-z0-9._-]*\.v[0-9]+$` |
| `time` | RFC 3339 UTC, not more than 5 minutes in the future, not older than the `events` retention |
| `datacontenttype` | `application/json` when present |
| `data` | JSON object when present |
| Size | One event at most `BROMO_MAX_EVENT_BYTES` (default 65536) |

A batch is validated as a whole. If any event is invalid the response is `400` with `errors[].pointer` such as
`/3/id`, and nothing is stored. `200 OK` means every event is stored in the warehouse and the materialized views have
run for that insert.

```bash
curl -X POST http://localhost:8080/api/v1/events \
  -H "Content-Type: application/cloudevents+json" \
  -H "Authorization: Bearer $BROMO_API_KEY" \
  -d '{"specversion":"1.0","id":"evt_001","source":"my-app","type":"com.example.payment.v1",
       "time":"2026-06-19T10:30:00Z","data":{"amount":42.5}}'
```

```json
{ "accepted": 1 }
```

## 5. Pipeline status

`GET /api/v1/pipeline/status`

```json
{
  "status": "healthy",
  "observedAt": "2026-10-20T10:42:31Z",
  "freshnessSeconds": 2.1,
  "endToEndLagP95Seconds": 3.4,
  "throughputEventsPerSecond": 410.0,
  "rejectRatio": 0.0008,
  "reconciliation": [
    { "check": "raw_vs_events_and_rejected", "consistent": true, "difference": 0 },
    { "check": "events_vs_mart", "consistent": true, "difference": 0 }
  ]
}
```

`status` is `healthy`, `degraded`, or `unavailable`. The thresholds are configuration and documented next to the query.
The response is `200` whenever the status could be computed, and `503` when ClickHouse is unreachable.

This endpoint describes data pipeline quality. Process liveness and readiness live on the management port (section 9).

## 6. Metrics

`GET /api/v1/metrics` returns `{ "items": [ { "name", "unit", "description", "breakdowns": [...] } ] }`. Metric names
are lowercase `snake_case` identifiers such as `event_count`, `amount_sum`, `amount_p95`, `unique_subjects`. The
registry lives in code and mirrors the table comments the agent reads.

`GET /api/v1/metrics/{name}/series`

| Parameter | Rule |
|---|---|
| `from`, `to` | RFC 3339 UTC. Range at most 7 days. |
| `step` | `1m`, `5m`, `1h`. Minimum `1m`. Prometheus-style duration. |
| `breakdown` | Optional, one of the metric's `breakdowns` |
| `type`, `source` | Optional equality filters |

`422` when the range holds more than 5000 points per series. Unknown parameters return `400`. Queries run over `mart_*`
with bound parameters, and the browser never sends SQL.

```json
{
  "metric": "event_count",
  "unit": "events",
  "step": "1m",
  "series": [
    { "labels": { "source": "card-replay" }, "points": [["2026-10-20T10:40:00Z", 120], ["2026-10-20T10:41:00Z", 133]] }
  ]
}
```

Points are `[time, value]` pairs, the same compact shape as the Prometheus range query result.

## 7. Findings

`GET /api/v1/findings?from=&to=&severity=&kind=&status=&limit=&cursor=` returns a page, newest first.
`GET /api/v1/findings/{id}` returns one finding or `404`.

```json
{
  "id": "0192f6c0-7d3e-7c1b-9a6e-2b7f0c9d4e11",
  "createdAt": "2026-10-20T10:42:31.120Z",
  "kind": "contributor",
  "metric": "fraud_ratio",
  "window": { "start": "2026-10-20T10:38:00Z", "end": "2026-10-20T10:42:00Z" },
  "dimension": { "name": "source", "value": "merchant-gateway-b" },
  "severity": "high",
  "confidence": 0.82,
  "summary": "Fraud ratio rose about 4x between 10:38 and 10:42. One source accounts for most of the increase.",
  "evidenceSql": ["SELECT ..."],
  "suggestedQuestions": ["Which types changed for this source?"],
  "status": "complete",
  "model": "deepseek/deepseek-chat",
  "costUsd": 0.0021
}
```

| Field | Values |
|---|---|
| `kind` | `outlier`, `trend`, `contributor`, `driver` |
| `severity` | `low`, `medium`, `high` |
| `status` | `complete`, `budget_exhausted`, `error` |

## 8. Chat

`POST /api/v1/chat`, requires a chat token.

```json
{
  "message": "Explain this chart",
  "conversationId": "optional-uuid",
  "context": { "metric": "fraud_ratio", "from": "2026-10-20T10:30:00Z", "to": "2026-10-20T10:45:00Z", "breakdown": "source" }
}
```

`message` is 1 to 2000 characters. `context` is optional. It tells the agent which metric, time range, and breakdown the
user is looking at, so "Explain this chart" needs no typing. It is validated like the metrics series parameters. The response is `200` with `Content-Type: text/event-stream; charset=utf-8` and
`Cache-Control: no-store`. Each event is an SSE record:

```
event: token
data: {"text":"The fraud ratio rose because"}

event: sql
data: {"statement":"SELECT ..."}
```

| Event | `data` |
|---|---|
| `token` | `{ "text": "..." }`, a piece of the answer |
| `sql` | `{ "statement": "..." }`, a query the agent ran |
| `chart` | `{ "type": "line", "metric": "...", "series": [...] }` |
| `follow_up` | `{ "question": "..." }` |
| `done` | `{ "status": "complete" or "budget_exhausted", "tokens": 1234, "costUsd": 0.002 }` |
| `error` | A problem details object. The stream then closes. |

Rules:

- Failures before the stream starts return a normal problem response (`401`, `429`, `503`). After the stream starts,
  failures arrive as an `error` event, because the status line has been sent.
- A comment line `: keep-alive` is sent every 15 seconds so proxies keep the connection open. Caddy must disable
  response buffering for this path.
- The browser `EventSource` API only supports `GET` and cannot set an `Authorization` header. The UI therefore uses
  `fetch` and reads the response stream. Tokens are never put in URLs.
- There is no `Last-Event-ID` resume in `v1`.
- If the client disconnects, the gateway cancels the gRPC call so the agent stops spending tokens.
- Limits: `BROMO_CHAT_RATE_PER_MINUTE` per token and the daily spend cap. Both return `429` with `Retry-After`.

## 9. Management

Served on `MANAGEMENT_SERVER_PORT` (default 8081), never published to the internet.

| Path | Purpose |
|---|---|
| `/actuator/health/liveness` | The process is alive. Does not check dependencies. |
| `/actuator/health/readiness` | Ready to serve. Checks the ClickHouse connection. |
| `/actuator/prometheus` | Prometheus text format |
| `/v3/api-docs` | Generated OpenAPI document |

Metric names follow Prometheus guidelines: `snake_case`, base units, `_total` for counters, for example
`bromo_ingest_events_total`, `bromo_ingest_request_duration_seconds`, `bromo_llm_cost_usd_total`.

## 10. Event contract

CloudEvents 1.0 is the only contract. Event types are yours to define.

Required attributes are in section 4. Optional: `subject`, `datacontenttype`.

Mapping to the warehouse (details in [DATA.md](DATA.md#events-silver)):

| Event field | Column in `events` |
|---|---|
| `id`, `source`, `type`, `time`, `subject` | `event_id`, `source`, `type`, `time`, `subject` |
| `data.amount` | `amount` when numeric |
| `data.label` | `label` |
| Rest of `data` | `attrs` |

Event time (`time`) and ingest time (`ingested_at`) are separate. Queries use event time.

Example types shipped:

| Type | Source | `data` |
|---|---|---|
| `com.example.payment.v1` | Fraud dataset replay | `amount`, `label`, other features in `attrs` |
| `com.example.llm_completion.v1` | Synthetic generator | `provider`, `model`, `promptTokens`, `completionTokens`, `latencyMs`, `costUsd`, `status` |
| `com.example.feedback.v1` | Synthetic generator | `score`, `category` |

To add a type, send events with a new `type`. Nothing else is needed. To filter on a new field efficiently, promote it
from `attrs` to a column with an additive SQL file.

## 11. Internal gRPC

Between `bromo-app` and `bromo-agent` only. Never reachable from outside the compose network. Contract file:
`proto/bromo/agent/v1/agent.proto`.

```proto
syntax = "proto3";
package bromo.agent.v1;

import "google/protobuf/timestamp.proto";

service AgentService {
  // Streams the answer to a question about the warehouse.
  rpc Chat(ChatRequest) returns (stream ChatResponse);
}

message ChatRequest {
  string message = 1;
  string conversation_id = 2;
  DataContext context = 3;
}

message DataContext {
  string metric = 1;
  google.protobuf.Timestamp from = 2;
  google.protobuf.Timestamp to = 3;
  string breakdown = 4;
}

message ChatResponse {
  oneof event {
    Token token = 1;
    Sql sql = 2;
    Chart chart = 3;
    FollowUp follow_up = 4;
    Done done = 5;
  }
}

message Done {
  Status status = 1;
  uint32 tokens = 2;
  double cost_usd = 3;
}

enum Status {
  STATUS_UNSPECIFIED = 0;
  STATUS_COMPLETE = 1;
  STATUS_BUDGET_EXHAUSTED = 2;
}
```

`Token`, `Sql`, `Chart`, and `FollowUp` are small messages mirroring the SSE events. Rules:

- Package versioned (`v1`). Field numbers are never reused or renumbered. Only additive changes.
- Enums start with `*_UNSPECIFIED = 0`.
- The gateway sets a deadline of `AGENT_TIMEOUT_SECONDS` plus a margin. Cancellation propagates to the model call.
- Errors use gRPC status codes, mapped by the gateway: `INVALID_ARGUMENT` to `400`, `RESOURCE_EXHAUSTED` to `429`,
  `DEADLINE_EXCEEDED` and `UNAVAILABLE` to `503`, everything else to `500` without detail.
- `traceparent` is sent in call metadata.
- The server exposes the standard `grpc.health.v1.Health` service. Server reflection is disabled in production.
